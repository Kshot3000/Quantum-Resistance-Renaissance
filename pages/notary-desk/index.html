Notary envelope v1 — the spec

Anyone can verify a QTC Notary anchor without this desk. The remark bytes are:

FieldBytesValue
magic51 4E 4F 54 2F 31ASCII "QNOT/1"
algo01 or 020x01 = SHA-256, 0x02 = BLAKE2b-256
digest32 bytesthe document digest
labelcompact length + UTF-80–64 bytes, human description

Verification recipe (independent)

  1. Hash your document with the stated algorithm → compare with the envelope digest.
  2. Rebuild the envelope bytes exactly as above → hash them with Blake2-256 (the runtime's T::Hashing).
  3. Find the System.Remarked { sender, hash } event (pallet 0, event variant 5) carrying that hash — the block number is your timestamp, the sender is your attestor.

Honest limits

  • A timestamp proves a document existed no later than its block — it says nothing about authorship beyond the sender key, and nothing about the document's truth.
  • Remarks are public forever. Never anchor secrets or plaintext you wouldn't publish.
  • Plain remark (no event) is only discoverable by scanning raw extrinsics — prefer remark_with_event unless you need the cheapest footprint.
  • Fees quoted here are the exact length fee; the small weight fee depends on runtime benchmarks and is quoted separately where shown.
