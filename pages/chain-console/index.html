How this console works

The wire protocol

Quantus nodes speak JSON-RPC 2.0 over WebSocket — the same protocol every Substrate/Polkadot-SDK chain uses. Each request is {"jsonrpc":"2.0","id":1,"method":"system_chain","params":[]}; the node answers with {"jsonrpc":"2.0","id":1,"result":"Quantus"}. The id lets many calls share one socket — this console fires the node-identity recipe's five calls in parallel.

Subscriptions

A *_subscribe* call returns a subscription id, then the node pushes notifications on the same socket. That is how the live head feed works — no polling. Unsubscribe (or disconnect) when you are done; a forgotten subscription is a leak on the node.

Read first, write carefully

Everything here is read-only except author_submitExtrinsic, which is gated behind a review screen and an explicit checkbox. The console never asks for keys — it only moves bytes you already signed elsewhere (the Airgap Desk produces them).

Etiquette

wss://rpc.quantus.network is a shared public endpoint. Do not poll it in a tight loop from scripts — subscribe instead, cache aggressively, and run your own node for heavy work (the Node Operator Desk shows how).

Key facts this console relies on

  • SS58 address prefix 189, 12 decimals, 1 QTC = 1012 planck (chain/node/src/chain_spec.rs, runtime)
  • Account storage: System.Account map, Blake2_128Concat over the 32-byte account id — the same key derivation your wallet uses
  • Existential deposit 0.001 QTC — accounts below it can be reaped
  • txWatch_* methods are Quantus-specific pool-listener additions — the Mempool Desk is their full desk
