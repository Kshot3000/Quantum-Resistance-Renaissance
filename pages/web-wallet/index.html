The vault for the quantum chain

Real self-custody for QTC. Keys are forged in your browser with post-quantum ML-DSA signatures, addresses derive from the chain's own Poseidon2 hash, and the vault is encrypted before it ever touches disk. No accounts, no servers, no seed ever leaves this page.

✨ Create a new wallet

Forge a fresh 24-word recovery phrase and an ML-DSA keypair. Takes about a minute — write the words down.

📥 Import a wallet

Bring a wallet you already made here — or anywhere that uses the documented derivation.

💾 Restore a vault file

Load an encrypted vault backup you exported earlier. You'll still need its password.

📝 Write these 24 words down — now

This is the only time they are shown. Anyone with these words owns the wallet. Store them on paper or steel, never in a screenshot or cloud note.

    🔐 Encrypt the vault

    Pick a strong password. It encrypts the vault on this device (PBKDF2-HMAC-SHA256, 250,000 rounds + AES-GCM-256). It cannot recover your wallet — only the 24 words can.

    🔓 Unlock the vault

    Vault found on this device. Enter your password — decryption happens locally.

    Forgot the password? Re-import with your 24 words — but first remove the locked vault with “Forget this device”.

      📜 How the crypto was verified

      • Address = Poseidon2(public_key) (Goldilocks field) → SS58 prefix 189 — from qp-dilithium-crypto 0.6.1 traits.rs + quantus-cli address_format.rs.
      • Signature = DilithiumSignatureScheme::Dilithium65([sig 3309 B ‖ pubkey 1952 B]) — primitives/dilithium-crypto/src/types.rs.
      • Signatures are FIPS-204 with context QUANTUS_EXTRINSIC — signing_context.rs; plain-context signatures are rejected on-chain.
      • Extrinsic = Balances (pallet 2) · transfer_keep_alive (call 3) — runtime construct_runtime! + pallet-balances 46.0.0.
      • Extension pipeline order (12 extensions) read from runtime/src/lib.rs TxExtension; payload layout matches sp-runtime 45.0.0 SignedPayload.
