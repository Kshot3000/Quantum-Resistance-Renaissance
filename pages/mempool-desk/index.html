⚠ Zero-confirmation signals — read this first

  • A signal means a transaction requesting a transfer to your address entered the node's pool with a valid signature. It does not mean the transfer happened, or ever will.
  • The transaction may be dropped, replaced, or fail at execution — and anyone can craft a convincing-looking signal that never moves funds.
  • Never release goods, mark an invoice paid, or credit a balance on a signal alone. Confirm inclusion in a finalized block first (per the upstream txWatch docs).

Why the pool matters on Quantus

Quantus transactions are large — post-quantum ML-DSA signatures push a typical transfer toward ~7 KB — and the chain handles that with native transaction aggregation (claimed ~430 TPS design throughput). A fat mempool is where fee pressure shows up first: this desk reads it raw.

txWatch — the pool-listener RPC

A Quantus node addition (chain/docs/rpc_additions/transaction_pool_listener.md), built for point-of-sale payment detection:

  • txWatch_watchAddress(address) → subscription id
  • txWatch_transfer notifications: {tx_hash, from, amount, asset_id}
  • txWatch_unwatchAddress(subscriptionId) to release
  • Watches native transfers, asset transfers, and batch_all nests up to 4 deep
  • Error 5011 = invalid SS58 address

The 5-step receive flow (per upstream)

  1. Generate the invoice — QR with your address + expected amount.
  2. Open the txWatch subscription for that address.
  3. Wait for the signal — show “payment detected, confirming…”.
  4. Verify execution — wait for a finalized block and check the Balances.Transfer event or the balance.
  5. Unsubscribe when the payment screen closes.

Node-operator notes

  • Reconnect with backoff — WebSockets drop; this desk does.
  • txWatch has no per-method cap, but nodes bound it at --rpc-max-connections (100) / --rpc-max-subscriptions-per-connection (1024).
  • Batch payments fire one notification per matching transfer inside the same tx_hash — call data, not execution outcome.
  • Only port 30333 (P2P) is meant to be public; keep RPC 9944 and the miner port private or proxied.

Data honesty

This desk has no demo mode and no fallback dataset. Every number on screen came from the socket you connected, in the last few seconds — or the desk says plainly that it has no data. If your node gates author_pendingExtrinsics, the Mempool tab says so instead of inventing a pool.
